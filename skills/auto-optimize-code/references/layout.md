# What is on disk, and every flag

## The search directory

`$WORK` is the directory `init` was given; `autooptimize/` is one folder of it.
Everything else sits in one folder for the step that writes it, named for what
it holds and carrying no number.
The layout is defined once, in `autoopt.PATHS` (a path helper:
`work_path(work, key, *more)`); no other script spells these folders.

```
$WORK/
  autooptimize/          steps 2-4: the search's own record, below
  NOTES.md               generated by `stages.py`: the five stages and the next command (never edited)
  interview/             step 0: interview.md, TERMS.md, terms_raw/, known-bugs/
  inputs/                what the benchmark reads: data/, env/, toolchains/
  tests/                 step 1, new unit tests: suite/ (the clone the tests branch is made in), analysis/ (the reading of the existing tests), work/ (scripts, coverage inputs and outputs, bugs/)
  setup/                 step 2 scratch, at fixed names: gateproof/ (copies of A0 for planted faults), width/ (the concurrent-run measurement, emptied each time)
  finish/                step 5: final-report.md, archive/ (the copied winner: idea.patch, code/, README.md, result.json), speedup-breakdown/
  scratch/               anything disposable; step 5 may delete it
  dashboard.ipynb        stays at the top
```

Rules:

- **One folder per step, plain names.** A new file goes in the folder of the
  step that writes it. A folder is never named with a random suffix (`mkdtemp`
  names do not appear in `$WORK`).
- **`autooptimize/` is the search's own record** and is not reorganized: it
  holds the git worktrees.
- **A folder no step lists is left alone.** No search command reads, moves
  or prunes a folder under `$WORK` that is not in the tree above.
- **Disposable means `scratch/`.** `prune` touches only `autooptimize/`;
  `scratch/` is what step 5 removes with the user's yes, and nothing there is
  referenced by a record.

`init` creates `config.json`, `spec.md`, `state.json`, `ideas.md`,
`knowledge.md`, `tools/README.md`, `tools/checkers/README.md`, `reference/`,
`rounds/`, `repo.git/` and the baseline. In **repository mode** (`init
--repo`) each iteration's worktree is `iterations/<id>/src/`, with the records
above beside it (`references/repo-mode.md`, *Layout*).

A corrupt `config.json`, `state.json` or validation record stops
every script with `<file> is not valid JSON (…)`. Nothing is reset; fix or
restore the file.

`autooptimize/` holds a repository of its own and every run's outputs: add it
to the surrounding project's ignore list, if it has one.

## The git model

The repo is **bare**, so the baseline is a worktree like every other
iteration. `autoopt.py new --new-id A3 --parent A0` runs `git worktree add -b
autoopt/3 iterations/3 autoopt/0`, so A3 starts from exactly the code A0 ran.

`run_iteration.py` commits whatever is uncommitted in the worktree before the
first run, so `git -C iterations/3 diff autoopt/0..autoopt/3` is exactly the
idea A3 tried.

Artifacts stay out of that diff through `repo.git/info/exclude`, which every
worktree shares: `runs/`, `unit-tests/`, `cache/`, `probe/`, `__pycache__/`,
`result.json`, `report.txt`, `meta.json`, `README.md`, `notes.md`,
`check/`, `check.json`, `cold.json` and `*.npz`. `init` refuses a
`--copy` file that matches the list (`copied file(s) match the plain-mode
exclude list`), since no iteration would have it; put such inputs in
`reference/`. When a benchmark writes another large file into its own
directory, add it to that file, not to a committed `.gitignore`.

**Never delete `iterations/0`**: the baseline is the commit every other
iteration descends from. To drop an iteration, `git -C repo.git worktree
remove iterations/<id>` rather than `rm -rf`, or git keeps a stale
registration and refuses the next `new`.

## Version fields

`config.json`, `state.json`, every `result.json` and `ended.json` carry
`schema_version`, the version of their layout (1). It rises when a field
changes meaning or is removed, not when one is added. A file without it was
written before the field existed and reads as version 1. A tool outside the
skill that reads these files checks it.

`config.json`'s `skill.name` is the skill that made the search. Another skill
that writes the same layout (`auto-optimize-ml`) runs by other rules, so every
script refuses a search whose `name` is not `auto-optimize-code` with `this
search was made by the … skill`, and the search is read with that skill's
scripts. A search with no `name` was made before the field existed and is
accepted.

## state.json

```json
{
	"root": 43, "round": 17, "roots": [{"round": 1, "id": 0}],
	"loop": {"phase": 4, "open": false, "started": "2026-10-14…"},
	"band": {"id": 43, "spread": 0.0021, "measured": "2026-10-14…",
		"phase": 4},
	"mining": {"stage": 3, "done": 2, "started": "2026-10-14…",
		"finished": "2026-10-14…", "seen": [0, 1, 2]},
	"setup": {"status": "done", "started": "2026-10-14…",
		"finished": "2026-10-14…", "answers": [{"question": "…",
			"answer": "…", "on": "2026-10-14…"}]}
}
```

`setup` is step 2's: `status` is `open` while the setup subagent works,
`waiting` (with its `question`) while a question waits for the user, and
`done` once `setup --done` passed; `answers` keeps each question with the
user's answer.

`mining` is the idea miner's: the last stage opened and the last closed (one
is open while they differ), and the ids settled when the open stage started,
so the next stage lists only the READMEs written since. `new` copies `done`
into each `meta.json` as `mining_stage`.

`root` is the iteration new ones fork from, `round` the current round, and
`roots` each promotion in order. `band` is the noise band's reference: the
sample standard deviation of the runs of the root as it stood when the last
phase opened (`loop`); before the first phase the baseline's spread is used.

## config.json

Written by `autoopt.py init`, changed mid-search by `autoopt.py config`.

```json
{
	"task": "Make the word counter faster without changing its counts.",
	"command": "python3 bench.py --seed {seed} --out {out}",
	"objective": {"name": "seconds", "direction": "min", "unit": "s"},
	"gates": [{"name": "n_mismatch_vs_base", "op": "==", "threshold": 0}],
	"observers": [{"name": "peak_rss_mb"}, {"name": "compile_seconds"}],
	"runs_per_iteration": 5,
	"confirm_runs": 5,
	"staged": false,
	"gpus_per_agent": 1,
	"seed_base": 0,
	"build_env": {"CC": "gcc"},
	"timeout_seconds": 0,
	"gpu": true
}
```

| Field | Meaning |
|---|---|
| `command` | how one run is launched, from inside the iteration directory. **Must** contain `{seed}` and `{out}`; omitting either fails at `init` with `config.json "command" must contain both {seed} and {out}`. `{out_abs}`, `{iteration}`, `{src}` (the worktree: `iterations/<id>/src` in repository mode, the iteration directory otherwise) and `{cache}` (`iterations/<id>/cache/<first 12 characters of the commit>`, one compiler cache per commit: `references/measuring.md`, *A cached compile can outlive the edit*) are also substituted, shell-quoted, so never put a placeholder in quotes (`'{out}'`): `init` does not catch it, and the run splits the argument once a path holds a space. Write a shell variable as `$VAR`, not `${VAR}`, and double a literal brace; `init` refuses any other brace |
| `objective.direction` | `max` or `min` |
| `gates[].op` | `<=`, `<`, `>=`, `>` or `==`. With `tol`, `==` becomes \|value − threshold\| ≤ tol, which is how "the outputs must not move" is spelled; on the other four, `tol` loosens the threshold by that much |
| `observers` | recorded, never optimized, never gated; one dashboard chart each |
| `runs_per_iteration` | runs per iteration, one seed each, A0 included (`init --runs`, default 5) |
| `staged`, `confirm_runs` | off unless `init --staged`: screen at `runs_per_iteration`, then confirm to `confirm_runs` when the median nears the frontier. Otherwise `init` sets `confirm_runs` equal to `runs_per_iteration` |
| `gpus_per_agent` | GPUs one iteration holds, and so how many of its runs go at once. The runner pins each run to one of them through `CUDA_VISIBLE_DEVICES`. With `--no-gpu`, only how many runs an iteration starts at once |
| `seed_base` | the first seed. Run *i* uses `seed_base + i`, so every iteration runs the same seeds, 0–4 at the default count. Change it only to start a whole search on fresh draws |
| `timeout_seconds` | a run killed after this many seconds counts as failed; 0 disables |
| `gpu` | false when the benchmark needs no GPU, which also lifts the lease check |
| `skill` | `name` (`auto-optimize-code`), `version` (the skill's `VERSION` file) and `commit` (the skill's last commit, or null outside a git checkout) when `init` ran. `stages.py next` and `stages.py status` print one `NOTICE` line for each later commit (`autooptimize/skill-seen.json` holds the one last reported); nothing stops |
| `schema_version` | the layout version of the record files (*Version fields*) |
| `floor` | a minimized objective's smallest value worth measuring, or null. At or under it the search stops with the reason `floor`; the price table marks an A0 under 20 times it (`references/step2-baseline.md`, *The price of the base*) |
| `workers` | the worker, rank or thread count the task names, or null. Each run's process tree is sampled every 0.1 s for threads the kernel shows running; `result.json` `workers` holds the most seen at once, and `setup --done` refuses while A0's is lower |
| `gpu_command` | the machine's GPU allocator as the words before a command, which it runs with `CUDA_VISIBLE_DEVICES` set and releases at exit (`srun --gres=gpu:1`). `run_iteration.py`, `check_seeding.py`, `prove`, `end` and `final` start under it when they hold no lease (`references/step2-baseline.md`, *GPU leases*) |
| `promote` | `auto` (`init`'s default) or `orchestrator`: with `auto` each iteration's runner promotes it when it passes the default keep rule while its parent is still the root, then runs the closed round's approved validation; `orchestrator` for a keep rule in the user's words (`init --promote`, `config --set`). |
| `subagent_model` | `opus` (default), `sonnet`, `haiku` or `fable`: the model every iteration subagent is spawned with (`init --subagent-model`, `config --set`); `brief` names it on stderr |
| `checks` | optional. `compare` (a command with `{src}` and `{reference}`), `time`, `first_call`, `build`, `profile` (each with `{src}`; `profile` also `{out}`), `threads` (an int), set by `config --set checks.<key>=…` (`references/step2-baseline.md`, *Write the checks*). With `compare` set, the runner checks every iteration whose runs pass their gates, and `promote` needs a pass |
| `loop_handback` | settled iterations one orchestrator phase sees before it hands back (default 16; `config --set`) |
| `allow_build_changes` | `yes` lets an iteration change build files, a binary or library, a vendored tree or an assembly file (`references/subagent.md`, *Portability*); set by `config --set` |
| `tests` | optional. `{"command", "timeout_seconds", "path"}`, set by `init --tests` and `--tests-path` (default `tests`). `{src}`, `{iteration}`, `{out}`, `{cache}`, `{selected}` substituted (`references/repo-mode.md`, *The unit-test gate*) |
| `repo` | repository mode only, written by `init --repo`: `path`, `branch` and `commit` of the original at the copy, `remote` and `remote_url`, `dirty_at_copy` |
| `after` | the answers about everything after the search (`init --after JSON`, `config --set after.X=V`; `null` unsets a text or number). This skill's nine keys: `stop` (`ask`, `auto`), `budget_hours`, `disk` (`ask`, `keep`, `prune`), `pair_cap_hours` (4), `setup_questions` (`ask`, `recommended`), `oldest_toolchain_command`, `commit_trailer`, `tests_driver_edit` (`ask`, `yes`, `no`), `build_outputs` (`[]`); each is defined in `references/step0-interview.md`, *The questions*. `config --set after.X=V` creates the block when a config has none (`init --force` would drop the rest of the config); `autoopt.py config` prints it. A choice outside a key's is refused. Any other key is kept as it is, and `config --set` on it is refused |
| `external_validation` | optional. `{"command", "measures", "note", "approved"}`, and `"units"` added by hand. `approved` starts false and only `validate --approve` sets it (`references/external-validation.md`) |

## metrics.json — the contract every benchmark meets

One per run, written by the benchmark into `{out}`: the only interface
between the benchmark and the scripts.

```json
{
	"objective": 4.812,
	"gates": {"n_mismatch_vs_base": 0},
	"observers": {"peak_rss_mb": 1840, "compile_seconds": 2.3},
	"note": "the first call compiles; the timed call is the second"
}
```

- `objective` is required and must be a finite number.
- **Every configured gate must appear.** A run that does not measure a gate
  fails: `metrics.json has no numeric value for the gate "n_mismatch_vs_base"`. Fix
  the benchmark, then `--rerun`.
- A missing observer is recorded as null and does not fail the run.
- A flat key (`{"n_mismatch_vs_base": 0}` at the top level) is accepted as a
  fallback; nest under `gates` and `observers`.

## result.json — what the runner writes

One per iteration, and the source of truth for every table, summary, README
and chart. Read it rather than recomputing anything from `runs/`.

| Key | Meaning |
|---|---|
| `status` | `ok`, `gate-failed` (a gate broke on at least one run, or the unit tests failed), `error` (a run crashed, timed out, or emitted nothing usable), or `partial` (fewer runs than `runs_per_iteration`) |
| `stage` | `confirmed` when the iteration has its full count of runs, `screen` when it has fewer (`--runs` below the count, or an iteration a failure stopped). The keep rule and `setup --done` need `confirmed` |
| `objective` | `median`, `mean`, `std`, `min`, `max`, and every run's `values` |
| `gates[name]` | `op`, `threshold`, `values`, `median`, `worst`, `pass`, `n_violations` |
| `observers[name]` | `values`, `median`, `std` |
| `frontier_at_start`, `noise_band` | the frontier when the iteration started, and the noise band its keep verdict used |
| `runs[]` | per seed: `seed`, `dir`, `objective`, `seconds`, `gates`, `observers`, `note` |
| `failures[]` | per failed seed: `seed`, `error`, `dir`, `seconds` |
| `tests` | the unit-test verdict: `command`, `exit_code`, `pass`, `scope` (`subset` or `full`), `selected` (the test files, or null for the full suite), `reason`, `seconds` (this pass), `seconds_total` (every pass on this commit), `commit`, `log`, `removed` (the files the run created in the worktree). `null` when not configured, or when a crash or broken gate settled the iteration first |
| `keep` | the default keep rule against the parent, on every `ok` iteration with a parent that is not a control: `verdict` (`pass` or `fail`) and `why`; after the runner's promotion attempt, `promoted`, and `round_closed` and `validation` |
| `check`, `failed_check` | with the task's checks: `compare` (`verdict` `pass`, `differ` or `error`, `exit`, `summary`, `log`) and `cold` (`verdict`, `seconds`, `runs`, `parent_seconds`). A compare that did not pass (`differ` or `error`) makes the status `gate-failed` with `failed_check: compare`; a cold first call that crashes makes it `error` before any run, with `failed_check: cold`. `check.json` beside it keeps the record for the commit and the cached outputs it was judged against |
| `best_run` | the run directory of the best single run: its outputs are one sample, so compare nothing to it |
| `commit`, `branch`, `parent`, `prediction`, `round`, `category`, `title`, `topic`, `control` | the record of what this was; `prediction` is `{"delta", "basis"}` or null; `control` is true for a same-code control, which is never on the frontier |

Only `status == "ok"` is eligible for the frontier. A `partial` iteration
(`--runs` below the count) stays out of the frontier, `promote` and the pass
rate until a run at the full count overwrites it. The frontier, the frontier path, the winner and
`best_run` are four different things (`references/glossary.md`, *The tree* and *After the search*).

## `autoopt.py` — the search tree

`--id` names an existing iteration; `new` and `brief` take `--new-id` (or `--id`) for the one they create. `--id` defaults to the winner (`best`) in `path`, `final`, `end` and `archive`, to the root in `check`, `profile` and `validate`, and is required where one iteration is acted on (`finish`, `readme`, `promote`, `variant`, `restore`, `checkers`).

## `stages.py` — the stages and the next move

```bash
python3 $AO/stages.py status $WORK        # the five stages: interview, setup, search, final, finish
python3 $AO/stages.py render $WORK        # the same table, written to $WORK/NOTES.md
python3 $AO/stages.py next $WORK [--run]  # the one command or question that is next
```

Each stage is `not started`, `running` or `complete`, read from `state.json`,
`ended.json` and `finish/`. `next` prints the move and its kind (`run`,
`agent`, `wait`, `stop`: `references/main-session.md`); `--run` starts a `run`
move.

## `run_iteration.py` — one iteration

```bash
python3 $AO/run_iteration.py $WORK/autooptimize/iterations/3
```

| Flag | Meaning |
|---|---|
| `--runs N` | run N seeds instead of `runs_per_iteration`; below it, the iteration is `partial` |
| `--confirm-runs N`, `--stage {screen,confirm,all}` | a search made with `init --staged` only: override `confirm_runs`; stop after the screening runs, go straight to `confirm_runs`, or screen then confirm (the default) |
| `--rerun` | re-run seeds already measured on the current commit |
| `--no-promote` | never promote, whatever `promote` says, and run no external validation: a re-measurement of a settled iteration |
| `--full-tests` | run the whole unit-test suite instead of the subset; reuses finished runs, so on a settled iteration it runs only the suite |
| `--dry-run` | print the runs that would happen, and stop |
| `--background` | start the same call detached, writing `<iteration>/probe/runner.log` (ending `exit <code>`), and return: watch it with `autoopt.py wait` |

It refuses while `spec.md` has a TODO line (`--dry-run` excepted), and never on a busy machine: before A0's runs on a CPU benchmark it names each process outside the search above about 100% CPU over two seconds in its report (`busy at start:`) and `result.json` (`busy_at_start`). Exit code 2
means `status == "error"`; 0 means the iteration produced a verdict, including
`gate-failed`. Each run is in its own process group, so Ctrl-C or a timeout
kills the whole benchmark, not only its shell. A seed already measured on the
current commit is skipped, so an interrupted iteration resumes where it
stopped; one measured on an older commit runs again. Run on a settled
iteration after a gate changed, it re-judges the stored runs under the new
gate. When `notes.md` exists, it re-assembles `README.md` at the end.

## `check_seeding.py` — does the seed control what it should

```bash
python3 $AO/check_seeding.py $WORK/autooptimize/iterations/0
```

`--seed N` is the seed to repeat (default: the search's first), `--repeats N` the runs on it (2), `--others N` the runs on further seeds (2); `--scan-only` reads the source for unseeded randomness and stops; `--keep` keeps the `runs/seedcheck-*` directories and the compiler cache.

Exit codes: 0 OK, 1 WARNING (the same seed moved the objective by half or more
of what changing it did), 2 FAIL (different seeds gave identical answers), 3
refused or could not run. Its runs, in `runs/seedcheck-*`, leave the
iteration's own results untouched, and share one compiler cache, `{cache}`, at
`<iteration>/cache/seedcheck`, emptied before the check and removed after it
unless `--keep`. What to do about each verdict:
`references/step2-baseline.md`, *Seeding*.

## `paired.py` — paired separate-process timing, with a stopping rule

```bash
python3 $AO/paired.py --a DIR_A --b DIR_B --cmd "python3 probe.py --src {src}" [--env K=V …] [--min-pairs 8] [--max-pairs 24] [--alpha 0.005]
                       [--direction min|max] [--regex PATTERN] [--cap-hours H] [--run-timeout S] [--log FILE] [--json]
```

`--regex` is a pattern whose first group is the seconds on the command's last line, for output whose last number is not the time. `--cap-hours` exits 3 before the first pair when `--min-pairs` would take longer; a recorded run past `--run-timeout` seconds (default: ten times that side's unrecorded run, plus 60) is killed, and that exits 4. `--cmd` runs once per timing in a fresh shell with `{src}` and `{side}` (`a`/`b`) substituted; it prints the seconds as the last number on its last line and exits non-zero when its output is wrong. Each side gets `<dir>/.paired-cache` as its compiler cache. The stop rule is the exact two-sided sign test.

`verdict` is `B better`, `B worse`, or `no difference resolved` when 24 pairs
end with p ≥ alpha. It exits non-zero, having decided nothing, if any run
fails. Why the stopping rule is safe: `references/measuring.md`, *Paired
separate processes: `paired.py`*.

## `cold.py` — cold first-call time on empty caches

```bash
python3 $AO/cold.py --side NAME=DIR [--side NAME=DIR ...] --cmd "python3 first_call.py --src {src}" --scratch DIR [--reps 2] [--env K=V …] [--regex PATTERN] [--json]
```

Each run gets a new empty directory under `--scratch` as `NUMBA_CACHE_DIR`
(and the Triton and Inductor caches), created with `mkdtemp` and never
deleted. Sides alternate order each repetition. In `--cmd`, `{src}` is the
side's `DIR` and `{side}` its `NAME`; the command prints the first call's
seconds as the last number on its last line. Keep `--scratch` inside
the iteration directory.

## `preflight.py` and `lint_text.py` — checks without measuring

```bash
python3 $AO/preflight.py $WORK [--id A12]         # the iteration's own change, from its parent; default best
python3 $AO/preflight.py $WORK --id best --path   # the whole path, from the commit the search copied
python3 $AO/lint_text.py body FILE [--labels A0,A1]
python3 $AO/lint_text.py title STRING [--labels …]
python3 $AO/lint_text.py commits REPO REF BASE [--labels …]
python3 $AO/lint_text.py diff-comments REPO REF BASE [--labels …]
```

`preflight.py` exits 0 with no problem, 1 with problems (one line each,
`check: text`), 2 when refused (not a repository search, no such iteration).
`--path` also writes `$WORK/autooptimize/preflight.json` (`{winner, problems}`).
`lint_text.py` exits 1 listing every hit with its line. The checks and the
vocabulary: `references/promotion.md`, *The preflight*.

## The verdict, exactly

Every stage the runner runs, in order: `references/subagent.md`, *Checks
beyond the runner*. The status, from the first rule that applies:

1. A cold first call that crashed: no runs at all, `error`.
2. Any failed run: `error`.
3. Any gate broken on any run: `gate-failed`.
4. The unit tests, then the compare, when configured: a failure is
   `gate-failed`.
5. Fewer runs than `runs_per_iteration`: `partial`.
6. Otherwise `ok`.

On an `ok` iteration with a parent, not a control, the default keep rule
passes when the median beats the parent's by more than the noise band:
`parent − median > band` when minimizing, `median − parent > band` when
maximizing. The band is the wider of the reference spread (the standard
deviation across the root's runs, re-measured when each phase opens; A0's
before the first) and this iteration's.
